# النطاق المخصّص

افتراضيًا يُقدَّم موقعك من عنوان المنصّة:

```
https://<workspace>.pagehub.id/<website>
```

ومع نطاق مخصّص يُقدَّم من نطاقك أنت:

```
https://sweetcakes.com/
```

افتح **الإعدادات** ← **النطاق المخصّص**.

::: warning ميزة مدفوعة
الباقات التجريبية لا تستطيع ربط نطاق. تعرض الشاشة دعوة للترقية حتى تدعمها باقتك. راجع [الباقات والحصص](/ar/account/plans-and-quota).
:::

## خطوات الإعداد

### 1. أدخل النطاق

اكتب النطاق الذي تريده — نطاقًا جذريًا (`sweetcakes.com`) أو نطاقًا فرعيًا (`www.sweetcakes.com`، `shop.sweetcakes.com`) — ثم اضغط **التالي**.

يختار PageHub الطريقة الصحيحة تلقائيًا:

| شكل النطاق | الطريقة |
| --- | --- |
| نطاق جذري / apex (`sweetcakes.com`) | سجل **A** إلى عنوان IP الخادم |
| نطاق فرعي (`www.`، `shop.`) | سجل **CNAME** إلى مضيف الخادم |

سبب الاختلاف: كثير من المسجّلين لا يسمحون بـ CNAME على النطاق الجذري، فوجب استخدام سجل A.

### 2. أنشئ سجلات DNS

تعرض الشاشة التالية السجلات المطلوبة بقيمها وأزرار نسخ.

<Shot src="/img/website/domain-dns.webp">
قسم النطاق المخصّص في مرحلة DNS: جدول بثلاثة صفوف (التحقق من الملكية TXT، توجيه الزيارات A/CNAME، توجيه www اختياري)، لكل صف نوع ومضيف وقيمة وزر نسخ وشارة حالة «قيد الانتظار».
</Shot>

عادةً ثلاثة سجلات:

| السجل | الغرض |
| --- | --- |
| **التحقق من الملكية** (TXT) | يثبت أن النطاق لك |
| **توجيه الزيارات** (A أو CNAME) | يوجّه الزوّار إلى خادم PageHub |
| **توجيه www** (اختياري) | ليصل `www.` إلى الموقع نفسه |

افتح **إدارة DNS** لدى مزوّد نطاقك (Cloudflare، GoDaddy، Namecheap وغيرها) وأنشئ السجلات كما هي مكتوبة تمامًا.

### 3. افحص DNS

اضغط **فحص DNS**. يحصل كل صف على شارة حالة:

| الحالة | المعنى |
| --- | --- |
| **مثبّت** | وُجد السجل والقيمة مطابقة |
| **قيد الانتظار** | لم يظهر بعد — انتشار DNS يستغرق عادةً 5 إلى 30 دقيقة |
| **غير مطابق** | السجل موجود لكن قيمته مختلفة. أعد نسخها |
| **تعذّر الفحص** | لم يستطع PageHub قراءة DNS حينها؛ أعد المحاولة |
| **يحتاج إعدادًا** | لم تنشئ هذا السجل بعد |

عندما تكون الحالات كلها خضراء تتحوّل الحالة إلى **فعّال** ويُقدَّم موقعك من ذلك النطاق.

## Cloudflare

إن كان DNS لديك في Cloudflare، فاضبط السجلات على **DNS only** (السحابة **الرمادية**، لا البرتقالية) أثناء التحقق وإصدار شهادة SSL الأولى. الوكيل البرتقالي يخفي السجل الأصلي فلا ينجح التحقق أبدًا.

## بعد تفعيل النطاق

تتغيّر أمور تلقائيًا:

- **عنوان المنصّة يحوّل إلى نطاقك.** تفاديًا لوجود محتوى واحد على عنوانين (وهو ضار بتحسين الظهور)، يحوّل `<workspace>.pagehub.id/<website>` تحويلًا دائمًا (301) إلى نطاقك.
- **canonical وخريطة الموقع والتغذية تنتقل معه.** كل وسوم canonical ومدخلات `sitemap.xml` وسطر `Sitemap:` في `robots.txt` تشير إلى نطاقك.
- **`robots.txt` يصير ملكك بالكامل**، لأن النطاق غير مشترك مع أحد. راجع [محركات البحث والذكاء الاصطناعي](/ar/seo/search-and-ai-discovery).

## فصل النطاق

زر **فصل** يفكّ ارتباط النطاق. ويعود الموقع للعمل على عنوان المنصّة. أما سجلات DNS لدى مزوّدك فعليك حذفها بنفسك.

## إذا توقّف الاشتراك

النطاق المخصّص ميزة اشتراك. فإذا مرّت مهلة السماح دون دفع، يتوقّف تقديم الموقع من النطاق المخصّص — لكنه يبقى متاحًا على عنوان المنصّة. التفاصيل: [عند توقّف الاشتراك](/ar/account/subscription-lapse).
